**This file records evidence, not a release declaration.** Historic ~93% engineering estimate is not a road-legality or production-ready percentage.

## Release process and evidence rules
1. Every row marked **PASS** must link an *actual completed* review, workflow, commit or independent source. A successful fixture or API-smoke test does **not** establish road legality. Reuse previous passing tests; rerun only when their relevant source changes.
2. **BLOCKED EXTERNAL** means a credible non-phone attempt could not establish the requested fact (e.g. up-to-date physical bollards/road signs or live TomTom key). Record the precise missing source and preserve the caution; do not silently mark PASS. Keep work moving on all independent rows.
3. **DEFERRED PHONE/FIELD** rows stay outside the **non-phone done** claim. They may remain open at phone-test notification *if explicitly disclosed*. Do not claim an app is legal for driving.
4. No changes to original Mterms app or unrelated oil-and-gas pages, secrets, MongoDB source data, or production TomTom authority. Heroku is the only approved JALAN backend; Railway stays unused.
5. A live pilot deployment remains **manual-only**. Do not auto-dispatch a release, and never ask for passwords, GPS tracks or API keys in chat. A workflow success is not a physical Safari test.

## Separate acceptance stages (never conflate)
- **Engineering / non-phone checkpoint:** Reviewed code and desktop/browser/API/security tests, coherent release/rollback, no unresolved implementable blocker. This leads to a *single* invitation for a **stationary** real iPhone/Safari test. It is **not** production driving authorization.
- **Actual phone checkpoint:** Owner tests private pilot stationary for interaction/safe-area/accuracy/diagnostics; failures feed a consolidated repair round rather than repeated ad hoc tests.
- **Road legality and release checkpoint:** Human or authoritative independent review of physical signs, pedestrian areas, permitted stopping and 20 real KL journeys, including current TomTom geometry/traffic evidence. This may not be completed remotely or by an API mock; the experimental preview must continue to say **not verified for legal driving**. Only after KL acceptance consider Peninsular Malaysia; East Malaysia later.

## Operating instruction
For each hourly run: **read `JALAN_PROJECT_HANDOVER.md` first**, choose the highest-impact unfinished **non-phone** item, do the actual work with supporting evidence, update the handover with any substantive milestone and update this checklist when status genuinely changes. Do not create tiny patches for appearance-only changes or duplicate already successful tests. When an external source cannot be verified, mark it blocked with dates and continue other tasks. If the user writes “go”, continue this workflow; **never treat “go” as a request to start phone testing before the non-phone gate**. At genuine completion deliver the exact required notification regardless of the wording of the latest user message.
